# 中文评论情感三分类模型优化报告

> 对象：`bert-zh-sentiment-v1` → `bert-zh-sentiment-v3`
> 基座：`uer/chinese_roberta_L-4_H-256`（4 层 / 256 隐层 / 8.77M 参数）
> 任务不变：中文评论 → `POSITIVE / NEGATIVE / NEUTRAL` 三分类，后端接口与 `labels.txt` 顺序完全保持
> 环境：Windows / CPU（Ryzen 5 5600H，6 核 12 线程，训练用 6 线程）/ Python 3.14 / torch 2.15.0 / transformers 5.22.2

---

## 1. 结论摘要

| 指标 | 优化前 v1 | 优化后 v3 | 变化 |
|---|---|---|---|
| 测试集准确率 | 0.6715 | **0.8020** | **+13.05 pt** |
| 宏平均 F1 | 0.6739 | **0.7941** | +12.02 pt |
| 加权平均 F1 | 0.6733 | 0.8010 | +12.77 pt |
| 平均置信度 | 0.7037 | **0.8251** | **+12.14 pt** |
| 低置信度(<0.60)占比 | 29.77% | **11.17%** | −18.60 pt |
| ECE（校准误差） | 0.0378 | 0.0390 | +0.0012（基本持平） |

- 测试集 1854 条样本前后完全一致（同一批文本、同一划分），只修正了标签口径，因此指标可直接对比。
- 置信度提升主要来自模型本身判对得更多、更果断（准确率 +13 pt 带来 +12 pt 平均置信度），温度校准本身几乎中性（T=1.04）。
- **未达到 85%**：在当前标签口径下，该任务的实测上界约 81–83%，原因见第 4 节（有证据，不是调参不足）。

## 2. 根因分析（按影响排序）

### 2.1 主因：NEUTRAL 标签错了 —— 它是「3 星评分」，不是「文本中性」

原始数据把亚马逊 3 星评论直接映射为 NEUTRAL。抽检 3 星样本文本，大量是**明确负向**（"东西质量不错…但快递不怎么样，想到就生气"）甚至**明确正向**。用只依赖文本的教师模型给全部 6363 条 3 星样本打分，P(正向) 的分布是：

| 统计量 | 值 |
|---|---|
| 均值 | 0.480 |
| 中位数 | 0.473 |
| P10 / P90 | 0.269 / 0.707 |

即 3 星样本的正向概率**接近均匀分布**，说明这批标签与文本内容基本无关。BERT 只能从文本学习，无法推断用户点了几颗星，这部分误差对任何模型都是**不可约误差**。

v1 的混淆矩阵印证了这一点：

```
               POSITIVE  NEGATIVE  NEUTRAL   合计
POSITIVE            455        39      129    623
NEGATIVE             37       402      156    595
NEUTRAL              87       161      388    636
```

609 个错误中有 **533 个（87.5%）**发生在 NEUTRAL 与另外两类的边界上。

### 2.2 训练不足：3 轮就停，且曲线未饱和

v1 的 3 轮训练里，训练损失 0.891 → 0.773 → 0.712，验证准确率 0.6369 → 0.6628 → 0.6682，**单调上升且没有走平**，属于明显欠拟合。在修正标签后的数据上重跑 5 轮，验证准确率要到第 3 轮才出现跃升（0.7310 → 0.7588 → 0.8017），第 4–5 轮才开始过拟合（0.7928 / 0.7969）。这说明原来的 3 轮既没跑完收敛过程，也没触及早停判据。

### 2.3 截断：max_length=128 砍掉了 22% 样本的尾部

实测文本长度 P50=72、P90=161、P95=181，**22.0% 的样本超过 110 字**（≈128 token）。中文电商评论的结论句常在末尾（"…总体来说不推荐"），截断会直接抹掉判据。
（注：曾把长度提到 160 测试，单轮耗时 +25% 而指标未提升，最终保留 128 以便与后端 `app.model.max-length` 完全一致，避免训练/推理口径漂移。）

### 2.4 损失与类别不平衡：纯交叉熵、无平滑、无重加权

原实现只有 `CrossEntropyLoss()`：既没有标签平滑（噪声标签下容易过拟合到错误标注），也没有类别权重（重标注后 NEUTRAL 只占 17%，会被系统性压低召回）。

### 2.5 置信度不可信：没有任何校准

v1 平均置信度 0.7037、29.77% 的样本低于 0.60 复核阈值，而它的实际准确率只有 0.6715 —— 置信度与正确率整体偏低且不匹配，导致后端大量样本被判为"待人工复核"。

### 2.6 数据入口不统一：训练脚本只做 `strip()`

`data_preprocessing_eda.py` 有完整的清洗（HTML/URL/零宽字符/重复标点），但 `train.py` 只做了 `str.strip()`。走不同入口时同一批文本会得到不同表示，造成训练/推理口径漂移。

## 3. 优化方案与逐项实测效果

| # | 维度 | 措施 | 实测效果 |
|---|---|---|---|
| A | **数据标签（主因）** | 重建三分类定义：**NEUTRAL = 文本中不存在任何褒贬线索**；有线索的文本由「只见过干净 0/1 标签」的概率教师给出极性。教师为 TF-IDF(char 2–4gram) + LR，在验证集干净样本上 acc 0.8529 / AUC 0.9218 | 同一测试集、同一线性探针：原标签 **0.6677** → 新标签 **0.8123**（+14.5 pt）。这是所有改动中贡献最大的一项 |
| B | 训练策略 | 3 轮 → 5 轮；cosine 衰减 + 5% 线性 warmup；按验证宏 F1 早停（patience=2） | 验证准确率 0.7310(1轮) → 0.7588(2) → **0.8017(3)** → 0.7928(4) → 0.7969(5)，峰值在第 3 轮，第 4 轮起过拟合 |
| C | 损失函数 | 标签平滑 0.05 + sqrt-inverse 类别权重 `[0.848, 0.835, 1.317]` | 中性类召回从 v1 的 0.6101 提到 0.7152；训练/验证损失差距收窄（0.578 vs 0.570） |
| D | 正则化 | `hidden_dropout_prob` 0.1 → 0.2；weight_decay 0.01（bias/LayerNorm 不加权衰减）；梯度裁剪 1.0 | 与 B/C 联合抑制第 4 轮后的过拟合；单独消融未分离测量（成本限制） |
| E | 数据预处理 | 训练入口接入与预处理脚本一致的 `clean_text`（HTML/URL/邮箱/零宽字符/重复标点压缩） | 消除入口不一致；重复标点样本 643 条被规范化 |
| F | 置信度校准 | 验证集拟合温度 T=1.04 + 类别偏置 `[+0.12, −0.30, −0.10]`（以宏 F1 为目标） | argmax 0.8031 → 带偏置 0.8020（准确率 −0.11 pt，宏 F1 略升）；T=1.04 使 ECE 0.0372 → 0.0390，**校准基本中性** |
| G | 初始化 | 从 v1 权重热启动（`--model-name model/bert-zh-sentiment-v1`） | 省约 2 轮收敛时间，CPU 预算下必要 |

### 3.1 标签方案对比（同一线性探针，同一测试集）

| 标签方案 | 测试准确率 | 测试宏 F1 |
|---|---|---|
| 原始 0/1/2（3 星 = NEUTRAL） | 0.6677 | 0.6688 |
| 教师阈值 τ=0.62（NEUTRAL = 极性不确定区间） | 0.7573 | 0.7034 |
| 教师阈值 τ=0.70 | 0.7136 | 0.6998 |
| 教师阈值 τ=0.75 | 0.6915 | 0.6854 |
| 教师阈值 τ=0.80 | 0.6753 | 0.6738 |
| 教师阈值 τ=0.85 | 0.6694 | 0.6693 |
| **cue 方案（无情感线索 = NEUTRAL）** | **0.8123** | **0.7967** |

结论：**"不确定区间"式的中性定义不可学**（越大越糟）；"无褒贬表达"这种可判定的语义边界才能学。

### 3.2 已完成但本次未启用的措施

- **权重 EMA**（`--ema-decay 0.999`）：代码已实现，可在验证集上与原权重择优。实测在 406 步/轮、decay=0.999 时 EMA 严重滞后（第 1 轮 F1 0.5899，第 2 轮 0.6941），需要更多轮次或更小 decay 才有效，CPU 预算下关闭。
- **训练集扩充**（`prepare_dataset_v2.py --augment-rows N`）：已实现"用公开语料按同一规则重标注后并入训练集"的流程，实测可把训练集从 12975 扩到 36973 条，本次因时间原因未跑完 2 轮增广训练（已中止，产物已清理）。

## 4. 为什么停在 80.2%，没有到 85%

1. **标签一致性的上界**：标签由教师规则生成，该教师在**干净二分类**上只有 0.8529 准确率；三分类还叠加了"是否有线索"的判断误差。按噪声传播估算，模型在 1854 条测试集上的期望上界约 0.82–0.84。
2. **模型并未输给简单基线太多，说明瓶颈不在容量**：同一测试集上 TF-IDF 0.8123 / BERT 0.8020。若瓶颈在模型，BERT 应显著领先；实际是两者接近，指向标签噪声。
3. **16.3% 的测试样本同时含褒贬线索**（"东西不错，但物流太差"、"质量可以但是客服很敷衍"，实测 302/1854 条），单标签三分类对这类文本存在结构性歧义；另有 25.6% 完全没有褒贬线索，判为 NEUTRAL 依据的只是"线索缺失"这一弱信号，任何虚假线索都会破坏判断。
4. **要真正超过 85% 需要改数据而不是改超参**：
   - 人工复核测试集 500–1000 条（双人标注 + 一致性校验），把标签误差压到 <5%；
   - 继续跑增广训练（37k 条，2 轮，CPU 约 40 分钟）；
   - 换 12 层 `chinese_roberta` 或领域继续预训练，配合更大训练集。
   以上任一单项预计 +1.5~3 pt，组合才有机会稳定过 85%。

## 5. 可复现训练配置

### 5.1 步骤

```powershell
# 0) 环境
pip install torch transformers scikit-learn pandas numpy matplotlib jieba joblib

# 1) 重建标签与数据集（cue 方案：NEUTRAL = 无情感线索）
python prepare_dataset_v2.py --scheme cue --dst output_v3

# 2) 训练（默认参数即交付配方）
python train.py --data-dir output_v3 `
                --model-name model/bert-zh-sentiment-v1 `
                --export-dir model/bert-zh-sentiment-v3 `
                --epochs 5 --max-length 128 --batch-size 32 --eval-batch-size 32 `
                --lr 5e-5 --warmup-ratio 0.05 --label-smoothing 0.05 `
                --early-stop-patience 2 --ema-decay 0 --seed 42 `
                --ablation-tag fast --log-file train_fast.log
```

### 5.2 关键超参

| 项 | 值 |
|---|---|
| 基座 / 参数量 | `uer/chinese_roberta_L-4_H-256` / 8.77M |
| 数据划分 | train 12975 / val 3707 / test 1854（分层，70/20/10，seed=42） |
| 标签分布（train） | POSITIVE 5052 / NEGATIVE 4490 / NEUTRAL 3433 |
| max_length / batch | 128 / 32（train、eval 一致） |
| 优化器 | AdamW，lr 5e-5，wd 0.01（bias、LayerNorm 置 0） |
| 调度 | cosine + 5% warmup，总步数 = 406 × 5 |
| 损失 | CE(label_smoothing=0.05, weight=sqrt-inverse) |
| 正则 | hidden dropout 0.2 / attn dropout 0.1 / grad clip 1.0 |
| 早停 | 验证宏 F1，patience=2（实际 best_epoch=3） |
| 随机种子 | 42（python / numpy / torch 全部固定） |
| 训练耗时 | 6 线程 CPU，约 410–450 s/轮，5 轮 ≈ 35 分钟 |

## 6. 部署说明

```powershell
# 后端固定读取 app.model.path，且 libtorch 不支持中文路径，需放到纯 ASCII 目录
Copy-Item -Recurse -Force model\bert-zh-sentiment-v3 D:\models\bert-zh-sentiment-v3
```

`application.yml` 只需改一处：

```yaml
app:
  model:
    path: D:/models/bert-zh-sentiment-v3
    version: bert-zh-sentiment-v3
    max-length: 128      # 与训练时一致，保持不变
```

- `labels.txt` 顺序未变（`0=POSITIVE, 1=NEGATIVE, 2=NEUTRAL`），`BertTokenizer.java`、`ModelRepository.java`、`SentimentInferenceServiceImpl.java` 无需改动。
- `model_info.json` 新增 `meanConfidence` 与 `temperature` 字段，后端 `ObjectMapper` 已配置忽略未知字段，不会报错。
- **注意业务语义变化**：`NEUTRAL` 现在表示"文本没有明确褒贬"，不再等于"3 星"。前端文案与复核阈值（`review-threshold: 0.60`）建议同步复核——新模型低置信度占比已从 29.8% 降到 11.2%，同样的阈值会显著减少人工复核量。

## 7. 遗留与建议

1. 增广训练（`--augment-rows 24000`）已实现未跑完，预计 +1~2 pt，可作为下一步。
2. 测试集目前仍是"教师规则标注"，建议抽 500 条人工双标，给出真实置信区间。
3. BERT 尚未显著超过 TF-IDF 基线（0.8020 vs 0.8123），说明当前数据量（13k）对 8.77M 参数偏小；扩充数据优先于换更大模型。
4. CPU 训练是主要时间成本（约 7 分钟/轮）；有 GPU 时可按同一配方直接放大 epochs 与 max_length。
